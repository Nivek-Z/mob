# 平台守则与数据归属

本文记录用户确认的产品边界，维护前先阅读；主题契约见 [THEMES.md](THEMES.md)。

| 数据 | 权威存储 | 管理范围 |
| --- | --- | --- |
| 正文、文章封面地址、标签、状态 | GitHub `content/posts/` | 核心模型，主题共享 |
| 个人资料、社交链接、友链、站点信息、导航 | GitHub `config/site/` | 共用一份，不按主题复制 |
| 图库分类 | GitHub `config/gallery/` | 核心模型，主题共享 |
| 图库说明、分类归属、公开与展示状态 | GitHub `content/gallery/` | 核心图库模型 |
| 注册清单、默认主题 | GitHub `frontend/themes.json` | 主题切换声明 |
| 主题配置、默认值、校验声明 | GitHub `frontend/themes/<id>/` | 结构与 UI由主题自己定义 |
| 上传图片、音频、视频字节 | 私有 R2 | 通过 Worker 稳定 URL访问 |
| 上传会话、完整性记录、可丢弃缓存 | R2 | 运行状态，不代替文本配置 |

GitHub 保留文章与全部文本配置；不能把“对象存储”扩大为把正文和配置迁入 R2。既有文章保持原文。

## 图床

图库有独立分类页面和首页入口；后台支持上传、说明、分类、公开/展示状态、分页与删除。批量分类与公开设置在一次 GitHub 提交中成功或失败，不产生部分覆盖。

编辑器拖入/粘贴图片自动上传 R2、归入 `article-images`（文章插图）并插入永久 URL。失败保留输入并支持重试；上传字节与 GitHub 登记是不同步骤，重试复用已完成对象的 ID。

草稿上传默认私有。已发布文章引用、有效公共/主题配置引用或管理员显式公开的媒体可以访问稳定链接；图库只列出明确展示的资源。私有预览走管理 API。图库公开不能让草稿正文公开。

删除前检查全部文章（包括草稿）与公共/主题配置引用。R2 桶保持私有，不设置绕过 Worker 的公开域名。旧上传可登记进图库，不改变既有 ID 和 URL。

## 主题与配置

文本保存提交到对应 GitHub 文件，返回新 SHA 与 commit SHA。编辑携带旧 SHA；不能盲目覆盖。运行时 API可以读到新配置；源代码、静态资产与主题入口变化需要构建部署。

主题自由定义技术栈、页面、动效、JSON 结构、分组与后台 UI。后端只认识接入协议、存储边界、核心业务与权限。配置中的 R2 图片通过统一引用机制登记，字段名和层级由主题自由决定。

公共资料、社交/友链统一维护，主题决定如何呈现。访客选择改变本人界面；文章、图库、公共资料始终同一份。管理员控制默认主题和可用列表。

## 跨服务维护

配置与引用侧文件在同一 GitHub commit 中保存。关系性写入由同一协调器串行处理。R2 上传成功而文本登记失败时保留对象供重试，不制造半个配置 commit。

直接在 GitHub 修改数据需维护模型和引用，且不享有 Worker 删除协调保护。日志、前端与公开配置不包含令牌。新增功能时同步维护本页与各层 AGENTS.md。

主题预置装饰图是部署种子：固定入口第一次访问写入 R2，校验摘要后从 R2 返回。源文件为可重建初始化材料；新上传的用户媒体不提交 GitHub。SVG 图标与 HTML/CSS/JS属于代码资产。

图库索引采用一个不超过 512 KiB 的 GitHub JSON（最多 1000 项）。删除先撤销 GitHub 图库记录再删除 R2；R2 删除失败时对象保持私有且可从“导入已有 R2 媒体”重新管理。完整对象删除失败不可报告成功。
