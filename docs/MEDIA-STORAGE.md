# Git、R2 与媒体清理

Git 保存代码、文章、配置和已登记媒体的元数据。R2 保存上传文件的字节；Git 不包含用户上传的图片、音频、视频，也不包含 Cloudflare Secret 的值。完整恢复站点需要 Git 仓库、R2 文件以及部署所需的绑定和 Secret。

## 每类数据存在哪里

| 位置 | 内容 | 缺失后的行为 |
| --- | --- | --- |
| Git `content/gallery/items.json` | 媒体 ID、文件名、URL、MIME、大小、创建时间、说明、分类、标签、公开与展示状态 | 图库和显式公开授权依赖此索引；R2 扫描不会自动重建 Git 条目 |
| Git 文章与配置引用侧文件 | 文章/配置对媒体的引用 | 用于公开读取授权和删除保护 |
| R2 `media/<id>/<filename>` | 受管理文件的字节 | 用户上传没有 Git 文件副本；删除字节后不能仅凭元数据恢复 |
| R2 `theme-media/` | 已部署主题装饰图的 R2 副本 | 有对应部署种子时，下次访问可以重新写入 |
| R2 其他原始素材路径 | 直接放入 R2 的旧文件 | 纳入图床时创建管理副本，原文件和原链接保留 |
| R2 `.mob/media/<id>.json` | 已完成对象记录；登记前也是重试用的元数据 | 已登记对象可从 Git 恢复；未登记对象应先保留记录或显式扫描纳入 |
| R2 `.mob/uploads/<id>/` | 上传会话、分片 ETag/大小、完成或取消状态 | 进行中上传依赖它们，不能把这些状态当作可随时删除的缓存 |
| R2 `.mob/index/`、`.mob/content-index.json` | 文章索引缓存 | 从当前 Git 分支重新计算 |
| R2 `.mob/settings/public-references.json` | 公开配置引用缓存 | 核对当前 Git HEAD 后重建；上游失败时不沿用旧授权 |
| R2 `cache/github-activity/` | GitHub 按日提交统计缓存 | 重新读取绑定仓库的提交历史；失败按活动接口状态显示 |

上传会话由 Worker 创建；R2 创建底层 multipart uploadId，并为分片返回 ETag。Worker 将这些结果写入 `.mob/uploads/`。文件完成后写 `.mob/media/`，客户端再调用图库登记 API，把已完成对象的元数据写入 Git。这是两个独立步骤；登记失败可以重试原 ID。

## 辅助记录缺失时

已登记素材仍有 Git 元数据和 `media/` 文件时，Worker 可以恢复读取、私有预览、引用校验和删除操作。ID 与稳定链接保持不变；恢复时核对文件大小及 R2 明确的媒体 MIME，通用 `application/octet-stream` 或未设置的类型使用 Git 中登记的 MIME。GET 只在内存恢复记录，不写 Git、不补写 R2 记录、不改变公开状态。

未登记文件不因此自动公开。后台“批量登记历史上传”只遍历 `.mob/media/`；记录也已丢失的对象，使用“扫描 R2”显式纳入。规范的 `media/<id>/<filename>` 对象保留原 ID，其他路径创建受管理副本。进行中的上传和取消/删除状态仍会阻止错误纳入。

`cache/` 下的活动缓存，以及文章/引用缓存，可以删除后重建。只有所有需要保留的已完成文件都已登记到 Git、没有进行中上传、也不再需要旧会话重试时，整个 `.mob/` 才能作为辅助数据清除。它不是文章、配置或已登记图库的权威来源；其中的进行中上传状态仍有实际用途。

## 清理上传状态

两个主题的图床后台都提供“清理过期上传状态”，调用受管理员鉴权和 Origin 校验保护的 `POST /api/admin/uploads/cleanup`。每页最多扫描四个上传目录，界面继续请求直到游标为空。

- 会话原有效期为创建后 24 小时。尚在有效期内的上传状态保留。
- 已完成或已删除会话到期后清理会话、分片记录和状态；已完成文件、`.mob/media/` 与 Git 图库保留。
- 过期未完成上传先取消，取消状态至少再保留一天，之后可再次清理。取消不会删除已完成媒体。
- 已取消会话同时满足原有效期结束、取消后一天这两个条件才清理。
- R2 取消分片的临时故障返回 503 MEDIA_ABORT_FAILED；取消状态阻止继续完成上传，但会话与 uploadId 保留。过期清理先重试底层取消，确认成功或 R2 返回 NoSuchUpload（10024）后才删除会话和分片记录，不能把存储故障当作清理成功。
- 完成状态已写入、媒体记录写入失败时，清理先核对完成文件并保留媒体记录，供后续登记。

当前没有定时清理任务。清理后旧会话接口返回 `UPLOAD_NOT_FOUND`，已完成媒体继续按媒体 ID 访问。清理状态不是清空图床，也不会删除主题或旧素材的原始文件。

## 移除引用与删除对象

清空头像、正文插图或主题配置 URL，只移除该处引用。其他已发布文章、有效配置或显式图库公开仍可授权同一文件。额外媒体 ID 是独立引用，需一并移除才能撤销它。

图床“删除对象”先检查全部文章（包括草稿）和全部配置（包括停用主题）。存在引用时拒绝删除。允许删除后先撤销 Git 图库条目，再删除受管理 R2 文件；theme/legacy 的原始文件保留。R2 删除失败时保留可供重试的私有记录并返回错误，使用当前图库 SHA 重试原删除接口即可。
